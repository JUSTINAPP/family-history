# Proposed Supabase / PostgreSQL data model

**Current follow-up:** The live archive has been created (confirmed by the user). Private HEIC display previews, real bulk import and catalogue editing are now implemented locally. Apply **only migration 005** to the existing project; do not rerun first-install SQL. See [preview, bulk and cataloguing setup](preview-bulk-cataloguing.md) for current behaviour, deployment and limits. Earlier foundation status below is historical where it says the hosted schema is absent or bulk/preview processing is deferred.

## Executable foundation (current)

The authoritative minimum schema for this stage is the four SQL files under supabase/migrations, not the full future-model table inventory below. Implemented tables: profiles, archives, archive_memberships, invitations, people, archive_items, archive_item_files, recollections, recollection_audio, transcriptions, metadata_suggestions, comments, identifications, processing_jobs, activity_log and provenance. All use UUIDs; archive-owned rows and same-archive pointers use archive_id and composite foreign keys. Account profiles remain global; historical People never imply membership.

Files distinguish original/audio_original/display/thumbnail/transcription_source and immutable reserved/stored source receipts. Recollections preserve original contributor text. AI tables are empty/prepared; no provider writes are enabled. Sensitive tables have SELECT-only authenticated grants plus role-checked RPC writes, preventing privilege/evidence/author escalation through direct REST writes. Storage is private and source updates/deletes have no authenticated policy.

No fictional seed, initial user password or hard-coded email is present. Auth creates/backfills profile rows only. create_archive atomically creates a new Archive and the caller's first Admin membership. Names are free content; no Allen-specific IDs or ownership rules are used. Places/events/relationships/collections/stories/search remain proposed, not prematurely implemented.

These migrations have passed local PostgreSQL tests but are not applied remotely. See supabase-setup.md for installation and policy verification. The subsequent table inventory remains the proposed expansion model.

This is a design specification, not an applied migration. The runnable UI uses TypeScript fixtures. All primary keys are UUIDs, normally `gen_random_uuid()`. Use `timestamptz` for audit times and `date`/`daterange` for historical dates. Every archive-owned record carries `archive_id NOT NULL`, `created_at`, `updated_at`, `created_by` (nullable only for system actors), and `revision bigint` where concurrent editing matters. `profiles` and `archives` are the exceptions to the archive-owned convention.

## Evidence and uncertainty

`evidence_status` is one of `verified`, `family_reported`, `ai_suggested`, `uncertain`. These are explicitly different from numeric AI confidence and date precision. Suggested values live in `metadata_suggestions`, while canonical fields and link records contain an editor-accepted assertion with provenance. Acceptance does not automatically mean verified: an editor chooses family_reported, uncertain, or verified and must cite evidence to mark verified. A confidence of 0.99 is never proof.

Store date_text for the contributor's original wording, date_precision (exact / approximate / year / decade / range / unknown), and nullable range boundaries. “1950s” spans the decade; unknown has null bounds. Do not collapse unknown months/days to fabricated exact dates. Different assertions can conflict; retain both in provenance and record the accepted interpretation explicitly.

## Referential integrity and indexes

Every archive-owned entity has `UNIQUE (archive_id, id)`. Joins and owned pointers use composite foreign keys `(archive_id, item_id) REFERENCES archive_items(archive_id, id)` and likewise for people, files, places, collections, stories and jobs. This prevents cross-archive joins even under privileged code. Never rely on the UUID alone to prevent a leak. Profiles remain global, while references to contributor/editor identities must be validated against membership at write time. Keep departed contributors' attribution after membership revocation.

Add indexes on `(archive_id, created_at DESC, id)`, item kind/date ranges, every foreign key, relationship endpoints, pending suggestions, job status/next_attempt_at and full-text GIN fields. Page positions are unique within an item and page role; use a transaction/deferrable constraint for reorder. Derivative keys are unique, and `parent_original_id` must refer to an original of the same archive and item. Original content/keys/checksums are immutable after finalisation. A checksum identifies bytes, not historical authenticity.

CHECK nonnegative byte_size/page_order, dates with start <= end, confidence in [0,1] or null, no self relationship, and a valid original/derivative role-parent combination. Restrict direct deletes of originals and evidence; use an audited archival retention/deletion service. Preserve history when a person is merged; redirect identity with an alias rather than deleting source links.

## RLS strategy

Enable and FORCE RLS for every archive-owned table; revoke anonymous access. Use a narrowly scoped `SECURITY DEFINER` helper in a private schema, with an explicit `search_path`, that returns active membership for `auth.uid()`. This avoids recursive membership policies. Revoke broad function execution and grant only intended authenticated access. Do not let a user supply their role in JWT custom data as the only authorisation source.

| Capability                                                   | Viewer | Commenter | Contributor | Editor | Admin |
| ------------------------------------------------------------ | ------ | --------- | ----------- | ------ | ----- |
| Read archive records and approved files                      | Yes    | Yes       | Yes         | Yes    | Yes   |
| Comment, edit own comment                                    | No     | Yes       | Yes         | Yes    | Yes   |
| Create draft items and original reservations                 | No     | No        | Yes         | Yes    | Yes   |
| Edit own unverified draft before finalisation                | No     | No        | Yes         | Yes    | Yes   |
| Edit accepted catalogue / review AI / verify with provenance | No     | No        | No          | Yes    | Yes   |
| Manage membership, archive settings and retention            | No     | No        | No          | No     | Yes   |

SELECT: active membership in row.archive_id. INSERT: WITH CHECK membership + allowed role, actor = auth.uid(), and permitted initial evidence/review state. UPDATE: USING and WITH CHECK membership; archive_id immutable. Policies alone do not enforce field-level permissions: use restricted grants + transactional RPCs/triggers so a contributor cannot set verified or change contributed_by. Comment update checks author or editor/admin; delete is audited and role limited. Membership writes require an admin RPC that prevents removal of the final admin. Profiles are self-editable; only minimal directory fields are readable to co-members.

Workers use a limited database role/RPCs rather than broadly exposing service-role privileges. They can write processing_jobs, derivative files, raw transcriptions and pending suggestions for their assigned archive. They cannot write canonical historical metadata or reviewed text. Separate policies and triggers must enforce immutable originals and append-only provenance, including for routine worker paths.

Storage: private `archive-originals` and `archive-derived` buckets. Keys start with archive UUID and item UUID. RLS validates the path against the corresponding file row and active membership. Contributor creation is reservation-only, non-upsert; prevent direct overwrite/update/delete of final originals. Derived reads are membership-scoped. Signing happens only after membership checks; signed URLs are bearer capabilities with short expiry. Never use a public bucket for private material.

Before deployment, test anonymous access, every role, revoked memberships, two-archive reads/writes, forged archive IDs, cross-archive foreign keys, profile exposure, original overwrite/delete, editor review races and final-admin removal. This document is not a substitute for executed policies and adversarial tests.

`people_mentions` is a projection rather than a duplicate Person-link table: reuse `archive_item_people` with role `mentioned` for resolved accepted links. Unresolved names stay in `metadata_suggestions` with recollection/page/span evidence; a future `people_mentions` view can union accepted links and pending mentions with clearly distinct status. A user-mentioned “Aunt Margaret” does not automatically identify Margaret Wilson, nor create a family relationship.

Source audio uses `archive_item_files` with role original and media_kind audio; `recollection_audio` supplies its semantic association. Derivatives carry parent_original_id just like images. UI `Recollection` objects are a joined projection of these future tables, not a demand to store all transcript versions on the recollection row.

Add source_file_id/page_order, start/end offsets or timestamps to evidence links as appropriate. Historical original capture time, contributor recorded_at and system ingestion/processing times are distinct. Use archive membership to authorize at access time while retaining the contributor profile's attribution after suspension/removal.

### Integrity and enforcement additions

Invitation redemption serializes on the invitation row, verifies current token status/expiry and verified authenticated email, upserts the existing archive/profile membership and consumes the token in the same transaction. Resend invalidates previous tokens. Do not create new accounts by manually choosing passwords. Linked Person must belong to the same archive and is optional. Ownership transfer must validate an active Admin membership and require secure acceptance; last-admin checks serialize to prevent two admins simultaneously removing the final admin.

Commenter can propose an identification or recollection against an existing readable item, but cannot create a new uploaded archive item. Contributor can add source audio to their contributions. Only Editor/Admin can approve canonical metadata or reviewed transcription. AI workers may append raw transcripts and pending suggestions, not edit accepted assertions. RLS for audio and recollections is identical in scope to the linked item; private audio must not be publicly reachable simply because it is playable in a browser.

Activity summaries reference durable source/provenance events. Avoid storing sensitive email addresses or entire source text in broadly accessible activity payloads. Admin membership events and operational details may require stricter policies than general historical provenance. Exports include both source and interpreted layers and a format-versioned manifest, not just flattened catalogue fields.

## Archive-first ownership contract

An Archive is a named private container for historical material, not specifically a Family Archive. The initial record is **The Allen & Cork Archive**, slug `the-allen-and-cork-archive`, using the existing archive UUID. Other owners may name archives Our Wedding, Janice Allen, Kodaikanal Years, Family Letters, A property history or An artist archive. No schema rule requires a family or family-tree association.

| Archive field           | Database representation / rule                                                                                                                                                                       |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Identity                | `id uuid PRIMARY KEY`; immutable. All archive-owned content references this ID.                                                                                                                      |
| Name                    | `name text NOT NULL`, nonblank; freely named, not globally unique, no family-specific prefix.                                                                                                        |
| Slug                    | `slug text NOT NULL UNIQUE`, lowercase letters/numbers/hyphens; globally unique locator. A rename does not implicitly change it. A future slug change should preserve an alias/redirect.             |
| Description             | `description text`; historical context, not permissions.                                                                                                                                             |
| Cover image             | `cover_file_id uuid` nullable; composite `(id, cover_file_id)` references a same-archive file. The UI `coverImage` is a display URL projection, not the canonical file identity.                     |
| Owner                   | `owner_membership_id uuid NOT NULL`; composite `(id, owner_membership_id)` references `archive_memberships(archive_id,id)`. Owner is an active Admin, linked to a global profile through membership. |
| Created date            | `created_at timestamptz NOT NULL DEFAULT now()` immutable; distinct from created_by attribution and historical item dates.                                                                           |
| Privacy                 | constrained `members_only` or `owner_only`. Both are private. No public visibility is introduced.                                                                                                    |
| Settings                | `settings jsonb` for default invited role, invitation policy, AI/transcription/location preferences; identity/privacy/owner are first-class columns, not buried in JSON.                             |
| Members and permissions | `archive_memberships` references archive and profile; unique `(archive_id, profile_id)`, with an independently assigned role/status in each archive.                                                 |
| Historical content      | Referenced child tables with `archive_id NOT NULL`; see the boundary inventory below.                                                                                                                |

Owner membership introduces a bootstrap cycle. Create the archive and first Admin membership in one transaction using preallocated UUIDs and a deferred composite foreign key, rather than briefly permitting an ownerless public archive. Keep the owner active and Admin through protected transactional operations; ownership transfer requires authenticated intent/acceptance and audit. Do not duplicate a global owner/admin flag on profiles. An account may own several archives; do not add `UNIQUE(profile_id)` to memberships or ownership links.

`archive_id` determines the archive that owns each historical record. `created_by`, `contributed_by`, current archive name, a Person ID and a family ID do **not** determine tenancy. Removing a member or renaming an archive never moves/deletes its content or original files. Changing a record’s archive_id is disallowed in ordinary edits; any future cross-archive copy/import is explicit, authorised on both sides and preserves source attribution with new destination IDs.

### Ownership boundary inventory

The following are archive-owned: archive_items, archive_item_files (including original audio), people, families, family_members, relationships, places, events, tags, every item/entity join, comments, identifications, recollections, recollection_audio, transcriptions/reviews, metadata_suggestions, provenance, processing_jobs, activity_log, collections/collection_items, stories/story_items, invitations, ingestion sessions, export jobs, search documents and future embeddings. Every row carries archive_id, and every local relation enforces a composite same-archive foreign key. Search caches and storage prefixes use the same archive UUID.

`profiles` and Auth users are account-level. `archive_memberships` is the bridge: one account, many archive memberships, one independent role per archive. Optional `linked_person_id` points to a Person in that membership’s archive only; a historical person never grants access. Archives own people/places/stories/collections through child rows rather than giant arrays or user-global tables.

### Privacy and permissions together

Every read/write requires active membership in the row’s archive. With `members_only`, apply that membership’s role matrix. With `owner_only`, additionally require the caller’s active membership ID to equal owner_membership_id; other memberships remain stored but cannot access historical content. The owner remains Admin. Writes require both privacy access and the archive-scoped role/column/RPC policy. Derivative signing, originals, audio, search, export and processing endpoints use the same checks.

The archive default role applies only to newly prepared invitations. Changing it does not grant/change any existing member’s permissions, nor grant access without invitation redemption. Public access is not an option. Test owner-only denial for other active members, independent roles across multiple archives, cross-archive file/cover/person/owner references, and membership revocation. UI role previews and editable privacy settings remain mocked and cannot replace executed RLS.

## Preview/catalogue follow-up (migration 005)

`archive_items.last_edited_by` and `catalogued_at` record catalogue work; `updated_at` records edit time. Provenance stores before/after reported metadata. The purpose-aware `(item_id,page_order,purpose)` constraint allows source and display to share a page; a unique display-parent index makes retries idempotent. `parent_original_id` uses the existing archive/item composite FK. Originals keep their existing immutable record/hash/path; display rows are independently reserved/stored. `catalogue_item` allows Editors and Contributors editing their own unverified material; attributed recollections stay append-only.
